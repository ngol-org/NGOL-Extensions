# 計算式を渡して下地を加工する見本

計算式を文字列で渡すと、ホストが毎フレーム GPU で走らせる。
素材を書き出して上に重ねる形とは別物で、**下地の映像そのものに効く**。

| | 重ねる形 | ここの形 |
|---|---|---|
| 下地の映像 | 手を付けられない。上に別の絵を置くだけ | そのものが変わる |
| 用意するもの | 動画ファイル | 文字列 1 つ |
| 変えたいとき | 作り直して読み込み直す | 文字列を差し替える |

---

## 使い方

1. グラフを開き、`obs.source.filter` の `name` に**効かせたいソースの名前**を入れる
2. 実行する
3. 外すときは `remove` を立てて、同じ `filter` の名前で実行する

数値は `p1`〜`p4` で渡す。何がどれかは各グラフの説明に書いてある。

---

## 入っているもの

| グラフ | 何をするか | 時間で動くか |
|---|---|---|
| `shader-warn-tint` | 画面ぜんぶを赤へ寄せて脈打たせる | 動く |
| `shader-focus-blur` | 中央だけ残して周りをぼかす | 動かない（出しっぱなし向け） |
| `shader-glitch-slice` | 横の帯をばらばらにずらす | 動く |
| `shader-pulse-edge` | 輪郭だけを光らせて脈打たせる | 動く |

---

## 書き方

`float4 render(float2 uv)` を 1 つ書く。定型は渡す側で付くので要らない。

```hlsl
float4 render(float2 uv)
{
	float4 c = sample_at(uv);
	return float4(c.b, c.g, c.r, c.a);
}
```

使えるもの:

| 名前 | 中身 |
|---|---|
| `sample_at(uv)` / `image` | 下地の絵 |
| `uv_size` | 下地の大きさ（画素数）。`1.0 / uv_size` が 1 画素ぶん |
| `elapsed` | 載ってからの秒数。動きはこれで作る |
| `p1`〜`p4` | 外から渡す数値 |

`technique` を含む文字列を渡せば、包まずにそのまま使われる。

### 通らなかったとき

**下地は消えない。** そのまま通るので、映像が途切れることはない。
理由は応答の `json` の `shader_error` に入る。
`shader_preamble_lines` は前に付いた定型の行数で、構文の誤りの行番号はこの分ずれている。

### 数の混ざり方

計算は linear light で行われる。**画素の値をそのまま混ぜた結果にはならない。**
RGB(0,128,128) と赤を `lerp(..., 0.5)` すると (188, 92, 92) になる
（画素の値で混ぜたなら (128, 64, 64)）。狙った濃さにしたいなら、そのつもりで係数を決める。
