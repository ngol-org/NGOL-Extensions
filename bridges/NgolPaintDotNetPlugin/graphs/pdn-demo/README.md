# NGOL x Paint.NET デモ（`pdn-demo`）

**このブリッジのノードを一通り押して、効いたことをホストの画面で確かめるグラフ。**
9 ノード・6 グループ。上から順に押していけば、ホストが最初から .NET のときに何ができるかが一巡する。

`scripts/deploy.ps1` が `Graphs\pdn-demo.json` として配る。WebUI の Load Graph から開く。

## このグラフの決まり

グループは互いに独立していて、どれか 1 つだけ押してもよい。
グループ 4 と 5 はホストの見た目や挙動を変える。どちらにも元へ戻すノードが右側にある。

## 6 つのグループ

| グループ | 押すと何が起きるか | 使うノード |
|---|---|---|
| **1. ブリッジは載っているか** | ホストに自分が何者かを聞く。`bridge_registered` が true なら、ホストが自分のプラグイン機構でこのブリッジを見つけたということ。版と窓の題名はホスト自身の型から来る | `pdn.app.info` |
| **2. 何が読まれていて、どれくらいの大きさか** | 左はホストがプラグインとして読んだもの（このブリッジだけ）。右はホスト自身の効果アセンブリ。各行はマネージドの見え方（版・公開型）とネイティブの見え方（ファイルのどれだけが載っているか）を並べ、同じ名前で版の違うものが 2 つあれば名指しする | `pdn.plugins.list` |
| **3. ホストが開いている画像** | 大きさ・レイヤー数・レイヤー名を、ホスト自身のオブジェクトから読む。何か描くかレイヤーを足してもう一度押すと数字が追う | `pdn.doc.info` |
| **4. ホストの見た目を変える** | ツールバーの歯車と疑問符の隣にボタンを足す。押すと、NGOL が実際に待ち受けているポートでこのエディタが開く。右のノードがボタンを外す。ホストにはどちらの API も無いので、窓を辿って行う | `pdn.ui.webui_button` |
| **5. ホストのイベントに乗り、無い機能を足す** | 開いている画像が切り替わるときにホストが上げるイベントを購読し、画像ごとに浮いているツール窓の位置を覚える。右のノードが止める | `pdn.tools.remember_layout` |
| **6. 同じプロセスをネイティブ側から見る** | どのホストでも使える解析ノードがここでも動く。読まれているモジュールを大きい順に並べる | `ngol.code.module_list` |

グループ 6 だけノードの出どころが違う。ホストに合わせて書いたものではなく、
どのホストでも使える解析ノードをこの相手に当てたもの。ホストは .NET のアプリなので、
上のマネージドの見え方とこのネイティブの見え方は、同じ 1 つのプロセスの両面になる。

## 最初に押すもの

**グループ 1 から押す。** `bridge_registered` が true でなければ、この先のノードはホストの型に届かない。
置き方は [ブリッジの README](../../README.md) にある。

## 試してみるところ

| グループ | やってみること |
|---|---|
| 3 | 画像に何か描く、レイヤーを足す。押し直すと大きさとレイヤー名が追う |
| 4 | ボタンを足してから押す。開くのは設定に書いたポートではなく、実際に待ち受けているポート |
| 5 | 保存した画像を 2 枚開き、それぞれでツール窓を別の位置に置いてから、行き来する。窓が画像に付いてくる。位置は key-value store に置かれるので、ホストを再起動しても残る |

## 戻し方

| 変えたもの | 戻すノード |
|---|---|
| ツールバーのボタン | グループ 4 の右のノード |
| 画像ごとの窓の位置を覚える購読 | グループ 5 の右のノード |

ホストを終了すれば、どちらも残らない。ブリッジが置くのはホストが読みに来るフォルダの中だけで、外せば元に戻る。
