# AviUtl ExEdit2 のプラグインとして NGOL を載せる

ホストが読みに来るフォルダへ `.aux2` を 1 つ置くと、NGOL が同じプロセスで起動する。
外せば元に戻る。

**ホストへフックは掛けない。** 触るのはホストが公開している口だけで、
そこへ届かないものは「届かなかった」として書いてある。

```
data\Plugin\NgolForAviUtl2\
    NgolForAviUtl2.aux2      <- これがホストに読まれる
    Nodes\CustomNodes\cs\   <- このホスト向けのノード
    （NGOL の実行環境一式）

data\Script\
    NgolProbe.anm2           <- Lua プロキシ。これが無いと NGOL から Lua を実行できない
    NgolProbeLua.anm2        <- 同じもののもう一方の実行環境向け
```

---

## 何ができるか

| | |
|---|---|
| スクリプトから NGOL を呼ぶ | ホストのスクリプトモジュールとして `ngol` を登録する |
| NGOL からスクリプトを実行する | 式を積み、Lua プロキシが取りに来て実行する（下記） |
| 編集操作をノードから呼ぶ | オブジェクトの作成・設定値の読み書き・レイヤーの表示など 78 種 |
| 描かれた絵を取り出す | 画面を撮らずに、出力の大きさそのままで受け取る |

**スクリプト側から見ると、追加のモジュールが 1 つ増えるだけ。**
プラグインを外せば、そのモジュールが消えるだけで他は何も変わらない。

---

## 人間がやる操作は、どこまでノードから届くか

**すべて実測。**「届く」は、その操作を実際に行い、別の手段で結果を確かめたもの。

| 人間の操作 | 届く手 | 実測 |
|---|---|---|
| 任意のレイヤー・フレームに置く | `aviutl.edit.create_object` | 置いた |
| 効果を後から足す | `aviutl.edit.section_call` `create_effect` | 足した（ハンドルが返る） |
| 効果のパラメータを設定 | `aviutl.edit.object_item` | `範囲` を 5 → 20。読み戻しも 20 |
| オブジェクトを動かす | `aviutl.edit.section_call` `move_object` | 別レイヤーへ。**効果とパラメータごと移る** |
| オブジェクトを消す | `aviutl.edit.section_call` `delete_object` | 消えた（移動元も空を確認） |
| 持っている効果を一覧する | `aviutl.edit.section_call` `get_effect_list` | 名前と有効・無効が並ぶ |
| レイヤーの表示を切り替える | `aviutl.edit.layer_enable` | 切り替わる |
| 設定項目名・効果名を調べる | `aviutl.info.enumerate` | 推測せず引ける |
| 編集状態・カーソル位置を読む | `aviutl.edit.info` | `editing` / `playing` / `writing` |
| **再生する** | `ngol.win32.menu_command`（`表示 > プレビュー再生 > …`） | ⭐ `editing` -> `playing` |
| 描画を起こす | `aviutl.edit.render_scene` | 起きる |
| ホストの値を読む・書く | `aviutl.lua.eval` | `obj` の 67 キー。書いた値をスクリプトが読む |

### 描かれた絵を取り出す

**ホストは描画を頼まれると、出来上がった画素をそのまま渡してくる。** 画面を撮る必要は無い。

`aviutl.edit.capture_canvas` がそれを画像にする。

| | 画面を撮る | この道 |
|---|---|---|
| 大きさ | プレビューの縮小サイズ | **出力する大きさそのまま**（実測 1920x1080） |
| 写り込み | ⚠ 一覧・題・開いている場所まで入る | **絵だけ** |
| 他の窓の重なり | ⚠ 影響する | 無関係 |
| スクリプトの有無 | 無関係 | 無関係 |

⚠ **出力の大きさのままだと、確かめるには大きすぎる。**
見るのに掛かる量は**画素数で決まり、ファイルの大きさは関係ない**（中身が黒ばかりでも同じ）。
⇒ `max_width` で縮める（既定 640）。**1920 幅のままだと、640 幅の約 9 倍掛かる。**

⭐ **縮めるときは間引かずに平均を取る。** 間引くと細い線が消えて文字が読めなくなり、
「小さくても何が描かれたか分かる」という目的を外す。

⚠ **画素はコールバックの間しか有効でない。** プラグイン側でその場で写し、
`Ngol_TakeFrame` で渡す。⭐ **縮める・書き出すは NGOL 側で決める**——
ネイティブを薄く保てば、直すのにホストの再起動が要らない。

### ⚠ 確かめられていないもの

| | |
|---|---|
| **停止・一時停止** | 送れるが、**効いたことを確認できていない**。`edit_state` は再生モードに居ることしか示さず、動いているかは分からない |

### 操作を増やすのに、ネイティブの作り直しは要らない

編集操作は**名前の並び**として `AviUtl2SectionCallNode.cs` に写してある。
**並び順 x 8 がオフセット**なので、**`case` を 1 つ足せば新しい操作が呼べる**。

実例: `get_effect_list`（オブジェクトが持つ効果の一覧）は、
**引数の形を宣言する 3 行と `case` 1 つ**で足した。`.aux2` は触っていない。

⚠ **並びの先頭は関数ではない**（編集情報へのポインタ）。呼ぶとホストが落ちる。
⚠ **公式ヘッダーの宣言順そのまま**にしておくこと。手で数えると必ずずれる。

### 使い勝手として直したいところ（実測で踏んだもの）

| | |
|---|---|
| 読み取りだけの操作でも `apply` が要る | `get_effect_list` を読むのに `apply` を立てることになる |
| ⚠ エイリアスに書いた効果の順と、一覧の順が一致しない | 並べ直されることがある（実測） |

## ビルド

### 用意するもの

| | |
|---|---|
| Visual Studio 2022（C++） | C++20 を使う |
| CMake 3.22 以上 | VS に同梱のもので足りる |
| **AviUtl ExEdit2 Plugin SDK** | `plugin2.h` などが入っているフォルダ。**同梱していない**（版が動くため） |
| .NET SDK（win-x64） | `libnethost.lib` を使う。入っていれば自動で見つける |

### 手順

```
cmake -S plugin -B <ビルド先> -DAVIUTL2_SDK_DIR=<SDK のフォルダ>
cmake --build <ビルド先> --config Release
```

出来上がるのは **`NgolForAviUtl2.aux2`**（拡張子はホストが決めている）。

**SDK のフォルダを渡さないと止まる。** どこに在るかは環境ごとに違うので、既定値を持たせていない。

### ソースの文字コード

**このプロジェクトのソースは UTF-8 BOM 付きで保存する。**
SDK のヘッダーは cp932 で、コンパイラの文字コード指定は 1 つしか選べない。
BOM は指定より優先されるので、両方が正しく読まれる。

⚠ **BOM を落とすと壊れる。** 日本語コメント中のバイトが行継続として働き、**次の行を飲み込む**。
症状は「識別子が見つかりません」「構文エラー」で、原因の行とは無関係な場所に出る。

## 置き方

### スクリプトで置く

```
./scripts/build.ps1
./bridges/NgolAviUtl2Plugin/scripts/deploy.ps1 `
     -PluginBinary <NgolForAviUtl2.aux2 のパス> -HostDir <aviutl2.exe のあるフォルダ> `
     -NgolRuntime build\runtime
```

置き先は**ホストの決まりに従って決まる**。実行ファイルの隣に `data` フォルダがあればそちら、無ければ `%ProgramData%\aviutl2`。データフォルダを直に指したいときは `-HostDir` の代わりに `-Dest` を渡す。

| 引数 | |
|---|---|
| `-PluginBinary` | 必須。ビルドで出来た `.aux2` |
| `-HostDir` / `-Dest` | どちらか一方が要る |
| `-Port` | 待ち受けるポート。既定 11156 |
| `-NgolRuntime` | 必須。`scripts/build.ps1` が組んだ `build\runtime` |
| `-NodesOnly` | ノードの `.cs` だけ入れ替える。**ホストを起動したままでよい** |

⚠ **`-NodesOnly` 以外はホストを閉じてから実行する。** 起動中はプラグインを掴んだままなので、上書きが途中で失敗して古くも新しくもないフォルダが残る。スクリプトは起動を見つけたら止まる。

### 何が置かれるか

**書き先は 2 つある。**

| 置き先 | 中身 |
|---|---|
| データフォルダの `Plugin\NgolForAviUtl2\` | NGOL 一式（`-NgolRuntime` で渡したもの）＋ `.aux2` ＋ `ngol-config.json` ＋ ノードの `.cs` |
| データフォルダの `Script\` | `data/Script/` の `.anm2` |

⚠ **`.anm2` はプラグインの隣ではなくホストの `Script\` へ行く。** 落とすとプラグインは動いたままスクリプト側だけが死ぬので、症状はプラグインの不具合に見える。

### 初回の起動

1. ホストを起動する。**初回は許可を問われるので許可する**
2. **もう一度起動する** — 許可した回はプラグインが初期化されない

**分かりにくいのはここ。** 許可した直後はモジュール一覧に載るのに入口が呼ばれないので、
「読み込まれていない」と誤診しやすい。

**`.anm2` を足したり設定項目を増やしたりしたら、ホストの再起動が要る。**
ホットリロードで済むのはノードの `.cs` だけ。

### Lua プロキシの置き方

NGOL から Lua を実行するには、**`NgolProbe.anm2` を載せたオブジェクトを 1 つ置く**。
プラグインの側からスクリプトを起動する口が無いので、スクリプトの方から取りに来てもらう。

置き方の条件は緩い（すべて実測）。

| 置き方 | |
|---|---|
| レイヤーを**非表示**にする | **動く** |
| **透明度 100%** にする | **動く** |
| 使うフレーム範囲を覆う | **要る**（範囲の外では描画処理を通らないので動かない） |

⇒ **非表示のレイヤーへ、使う範囲を覆うように 1 つ置く**のが邪魔にならない。映像には影響しない。

**プレビューが描き直されないと、積んだ式はいつまでも実行されない。**
`aviutl.edit.render_scene` で自分から描画を起こせる。

### Lua を実行する道

`aviutl.lua.eval` の 1 本。**プロキシを置いた場所で走る。**

| | |
|---|---|
| 置くもの | オブジェクト 1 つ（`NgolProbe.anm2`） |
| ホストに触るか | 触らない。ホストがスクリプトへ出している口だけを使う |
| 所要 | 描画を待つ（起こして回収の 2 手） |
| `obj` などホストの拡張 | 使える |
| 相手のオブジェクト | 置いた場所 |
| 描画そのものへの割り込み | できる（`obj.draw` / `effect` / `pixelshader`） |

⚠ **`io` / `package` / `require` が使える**（実測）。制限されていないので、書くスクリプトはホスト自身と同じ権限で動く。

⚠ **どの描画でスクリプトが走るかは、こちらでは決められない。**
同じフレームを撮り直すと 1 度も通らない回がある（実測。条件は特定できていない）。
⇒ **時間切れは「届かない」ではなく「その回は走らなかった」でありうる。**

### 動いているかの確かめ方

`Plugin\NgolForAviUtl2\NgolForAviUtl2.log` に、起動のたびに記録が残る。

```
started (host version 2010500)
script module registered as 'ngol'
```

ホスト本体のログは既定でほとんど残らない（`[ERROR]` だけ）。
調べるときは `aviutl2.ini` の `[Logger]` を下げる。⚠ **ホストを終了してから書き換える**——
起動中に変えても終了時に上書きされる。

## 中身

| ファイル | |
|---|---|
| `plugin/plugin.cpp` | ホストの型を知っている唯一の場所。入口の登録と、NGOL 側へ渡す口 |
| `plugin/NgolBridge.*` | 実行環境を起こす。**ホストの型を持ち込まない** |
| `nodes/` | このホスト向けのノード |
| `graphs/` | 演出のサンプル 5 例。仕組みが違うものを 1 つずつ |
| `data/Script/` | ホストへ置く `.anm2`。**配置先と同じ形**にしてある |
| `scripts/` | 編集操作の呼び出し表をヘッダーから作る道具（**開発用。配布物ではない**） |

### 編集操作の呼び出しについて

編集操作は**名前を持たない関数ポインタの並び**で、番号でしか引けない。
番号と引数の宣言を別々に書き写すと、**片方だけ間違えても気づけない**——
正しい引数で隣の関数を呼ぶので、落ちずにもっともらしい値が返る。

だから両方を 1 つの道具で公式ヘッダーから出す（`scripts/`）。
並びは公式ヘッダーの宣言順そのままで、**版が上がっても末尾に足されるだけ**なので更新は要らない。

⚠ **並びの先頭は関数ではない**（編集情報へのポインタ）。呼ぶとデータの番地へ飛んでホストが落ちる。

---

## 外し方

データフォルダの `Plugin\NgolForAviUtl2\` を消す。ホストの設定も、作ったプロジェクトも変わらない。

`Script\` へ置いた `.anm2` は残るので、要らなければ併せて消す。置いた中身は `data/Script/` にある。
