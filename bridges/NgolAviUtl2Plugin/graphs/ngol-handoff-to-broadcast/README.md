# 素材を書き出して、もう 1 つのホストへそのまま載せる

編集ソフトで作った映像を透過つきで書き出し、**別のアプリのシーンへ載せて重ねる**まで、
1 本のグラフで通す見本。

2 つのアプリを繋いでいるのは `ngol.link.*` のノードだけで、人も外部の道具も間に入らない。

## 何が要るか

| | |
|---|---|
| 相手側 | NGOL が載っていて、待ち受けていること。ここでは配信ソフトのブリッジを使う |
| 符号化 | `ffmpeg`。`encoder_path` を自分の環境に合わせる |
| 書き出し先 | 両方のアプリから読める場所。**パスは `/` で書く**（JSON の中で `\` は別の意味になる） |

## 流れ

```
相手を探す          待ち受けている NGOL を名前で引く（番号を書き固めない）
      |
素材を書き出す      1 枚ずつ描かせて符号化へ流す。keep_alpha で透ける所が残る
      |
シーンへ載せる      前回の残りを外す -> メディアとして足す -> 画面いっぱいに広げる
      |
数で確かめる        相手に描かせて、素材の色が何割あるかを受け取る
```

## 確かめ方が要点

**人が画面を見ないで判定する。** 素材に 1 色だけの図形を置いておき、
相手の画面のうち何割がその色かを数える。

- 載る前は 0%、載った後は図形の面積ぶんになる
- ⭐ **透過が効いているかは、下の絵が隠れていないかで分かる**——
  素材を画面いっぱいに広げても下がそのまま見えていれば、透けている

⚠ **色は符号化を通ると動く。** ある実行では 0 を指定した成分が 39 になっていた。
`match_tolerance` を狭くすると、載っているのに 0% と出る。

## 差し替えるところ

| | |
|---|---|
| `name_contains` | 相手の名乗りに含まれる文字 |
| `output_path` / `encoder_path` | 書き出し先と符号化の道具 |
| `frame_from` / `frame_to` | 書き出す範囲 |
| `match_color` | 素材に置いた色 |

⚠ **相手が読んでいる最中のファイルは開いたまま**になる。作り直すなら、
別の名前へ出すか、このグラフのように**先に外してから**足す。
