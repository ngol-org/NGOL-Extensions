# ホストの編集操作を、ノードから呼べるようにする

編集操作は関数ポインタの並びで、実行時に名前は残っていない。番号でしか引けない。
番号と引数の宣言を**別々に書き写すと、片方だけ間違えても気づけない**——正しい引数で
隣の関数を呼ぶので、落ちずにもっともらしい値が返る。

だから両方を 1 つの道具でヘッダーから出す。

```
py gen_edit_section_binding.py <plugin2.h>                    一覧
py gen_edit_section_binding.py <plugin2.h> set_layer_lock     1 本ぶんの C#
```

出力はそのまま貼れる。貼って保存すれば数秒で反映される（ホストの再起動もビルドも要らない）。

## 3 手で足せる

| # | やること |
|---|---|
| 1 | 生成器に関数名を渡す |
| 2 | 出た `delegate` 宣言と 2 行をノードへ貼る |
| 3 | 保存する。ログに `Hot-reloaded` が出たら呼べる |

出力には ⚠ が付くことがある。**それは貼る前に読む**——下の「誤診の形」の再発防止として付けている。

## 呼べる場所は 1 か所だけ

```csharp
edit->call_edit_section_param(param, (param, section) => {
    // section が有効なのはこの中だけ
});
```

ヘッダーの原文で「編集情報を排他制御する為に更新ロック状態のコールバック関数内で」
「纏めて Undo に登録されます」「メインスレッドから呼ばれます」とある。
**ロックも Undo も区間の性質であって、関数それ自体の性質ではない。**
関数ポインタを控えて外から呼ぶと、そのどれも成立しない。

---

## 誤診の形（実際に間違えた読み方）

同じ推論の道に入った時点で止まれるように、**間違えた読み方をそのまま載せる**。

### 「番号は版が上がると変わるはずだ」→ 変わらない

公開ミラーの全 40 版を突き合わせた結果、**削除も並べ替えも 0 件**。
廃止する関数は消さずに `deprecated_` を付けて枠に残し、差し替え先は末尾へ足している。

⇒ **一度作った表は、新しい版でもそのまま使える。** 版ごとの表もアドレスの控えも要らない。

### 「`deprecated_` は機能が無いということだ」→ 生きている

中身は転送スタブで、**足りない引数を補って新しい実装へ渡している**。

```asm
mov r8d, 10h        ; 新設された第 3 引数に旧い既定値を補う
jmp  <新しい実装>
```

古いヘッダーでビルドしたプラグインは、**そのまま正しく動く**（実測で確認）。
ただし新しく書くなら差し替え先を使う。生成器は廃止された枠に警告を出す。

### 「引数の個数さえ合っていれば安全だ」→ 半分しか見えない

個数が同じで型だけ違う場合は素通りする。実例として、ベータ初期に
`void f(LPCWSTR)` の枠が `PROJECT_FILE* f(EDIT_HANDLE*)` に置き換わったことがある。
どちらも 1 引数なので、個数を数える検算では区別できない。

### 「番号は数えれば分かる」→ 先頭で 1 つずれる

**並びの先頭は関数ではない。** 0 番を関数として数えると、以降が全部 1 つずれる。
ずれても落ちない（隣の関数が正しい引数で呼ばれる）ので、値がおかしいと気づくまで進む。
生成器はこれを数え込んで出す。

### 「戻ってきた文字列は後で読めばいい」→ 読めない

文字列を返す関数の戻り値は、**次に同じスレッドで文字列を返す関数を呼ぶまで**しか
有効でないとヘッダーに書かれている。区間を抜けてから読むと別の内容になる。
**その場で写す。**

### 「文字列は文字列として渡せばいい」→ 化ける

`LPCWSTR` は UTF-16 だが、**`LPCSTR` はここでは UTF-8**。
C# の既定の写し方（ANSI）で渡すと日本語が化ける。生成器は `LPCSTR` を `IntPtr` で出す。

### 「引数の数を間違えたら例外が出る」→ プロセスごと消える

3 引数の関数を 2 引数で呼ぶと、**例外も記録も残さずプロセスが終了する**（実測）。
try / catch では捕まらない。だから手で書き写さずに生成する。

---

## この道具が要らない場合

**ホストのメニューと、スクリプトの `obj.*` は名前で解決される。**
そこに同じ操作があるなら、そちらの方が単純で版にも強い。
ここを使うのは、名前で引ける経路に無い操作だけでよい。
