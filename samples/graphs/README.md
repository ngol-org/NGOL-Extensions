# samples/graphs — ノードを繋いだ状態で配るグラフ

3 本あります。用途が違うので、目的に合うものから開いてください。

| ファイル | 何をするか | どこで動くか | 言語 |
|---|---|---|---|
| `analysis-nodes-showcase.json` | 解析ノード 41 本を繋がずに並べたもの。読み込んでも何も走らない。グループの説明がノードの家族ごとの役割と最初に押すノードを言う。ポートに触ると受け取るものと返すものが読める | どのホストでも | 英語 |
| `background-scan-with-wait.json` | 大きなモジュールをバックグラウンドで走査し、待ってから結果を読む。走査中もホストは止まらない。対象は `kernel32.dll` にしてあるので、どのプロセスでもそのまま実行できる | どのホストでも | 日本語 |
| `overlay-dice-on-target.json` | 対象アプリが描いた絵の上に回転するサイコロを重ねる。対象は絵の素材も描画のしかけも持たなくてよい | D3D11 で描く対象。題材アプリで試せる | 日本語 |

## 最初に開くもの

ノード一式を眺めたいなら `analysis-nodes-showcase.json`。実行して何かが返るのを見たいなら `background-scan-with-wait.json`。
題材アプリを起動しているなら `overlay-dice-on-target.json`。

## 開き方

組み立てと配置のスクリプトはこのフォルダを運びません。開きたいグラフを、NGOL が読む `Graphs/` フォルダへ写してから、
WebUI の Load Graph で開いてください。

```
題材アプリ    samples/apps/D3DTargetApp/build/dist/Graphs/
ブリッジ      各ブリッジの配置先にある runtime の Graphs/
```

## 重ね描きの 2 通り

`overlay-dice-on-target.json` は 2 ノードで、実行するとそのままサイコロが出ます。何度実行してもかまいません。

題材アプリの `samples/apps/D3DTargetApp/graphs/` にも同じ名前のグラフがあり、そちらは準備と描画に分かれています。
準備の側で画面へ出す呼び出しを見つけてスワップチェーンを捕まえ、描画の側で絵を出す組み方です。
題材アプリでは `prepare-dist.ps1` がそちらを `Graphs/` へ写すので、何もしなくても開けます。

## 待ちを挟むときの決まり

`background-scan-with-wait.json` は、同じ入力を持つ走査ノード 2 つの間に待ちを置いています。
左が走査を始めて即座に戻り、右が走り終えた結果を受け取ります。待ちを挟んでも手前のノードの出力は新しくならないので、
読むのは待った後に置いたノードのほうです。待ちが足りなければ `done` が false のまま返るので、`ticks` を増やすか右のノードをもう一度実行してください。
